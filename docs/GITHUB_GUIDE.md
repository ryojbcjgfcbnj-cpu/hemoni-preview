# 给项目作者的 GitHub 入门说明

## 常见栏目是什么意思

| 名称 | 可以理解为 |
| --- | --- |
| Repository / 仓库 | 项目的网上文件夹，保存文件和修改历史 |
| README | 仓库首页，介绍项目和使用方式 |
| Commit | 一次保存，有说明文字和可追溯记录 |
| Branch / 分支 | 单独修改的一条工作线 |
| Pull Request / PR | 请求把某个分支的修改合并回主线 |
| Issue | 问题、建议或待办，不要在这里贴密钥 |
| Release | 正式发布的版本，可附安装包 |
| Tag | 标记一个版本对应的代码位置 |
| GitHub Pages | 把静态文件发布为网站 |
| LICENSE | 说明别人得到哪些使用和修改权利 |
| Star | 收藏和关注项目，不是下载次数或用户数 |

## 如何改仓库名

在仓库 Settings → General → Repository name 修改名称。改名前记录 GitHub Pages 当前配置；改名后检查 Pages 新网址、README 链接和已有引用。不要创建同名旧仓库来占用原地址，否则可能影响旧链接跳转。

如果 Settings 中没有相应权限，需要仓库所有者操作。改名不是删除仓库。

## 如何维护

小改动可以直接在网页编辑文件，填写清楚的提交说明。较大的改动先建分支，再通过 PR 查看差异。发布版本前确认实际可用功能和已知限制，再整理 Release。

README 介绍当前状态；CHANGELOG 记录每次改变了什么；Issue 跟踪问题；Release 附经过确认的安装包。这几者用途不同。

## 简历放哪个链接

优先放仓库首页，让招聘者先看到项目介绍、技术架构和边界。演示链接作为补充。

如果你主要负责需求、设计、集成和验收，可如实写「负责产品设计、模块集成与功能验收，使用 AI 辅助开发」。不要将网页里的模拟数字当成项目实测成果。

## 公开前要检查

不要上传 config.yaml、.env、API Key、登录会话、Cookie、服务器管理凭据、私钥、内部材料或个人聊天记录。忽略规则只能防止以后误加入，不能删除已经进入 Git 历史的内容。
