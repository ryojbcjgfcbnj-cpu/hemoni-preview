# 较真一下 · AI 桌面助手与核查工作台

**把 AI 回答与原始材料放在一起，核对数字、引用和字段口径，并留下可追溯的修订记录。**

较真一下以桌面宠物为入口，连接文件管理、AI 回答编辑、金融材料核查、专家修订和社区交流。项目早期使用「和鸣 / Hemoni」名称，部分旧文件和页面地址仍保留这一名称。

> 本仓库目前是产品介绍与交互演示网站，不包含 Electron 桌面端完整源码。页面中的数据和交互用于演示，不连接真实核查、模型或社区服务。桌面软件能力与展示页实现请分别阅读。

## 直接体验

打开 [在线工作台](https://ryojbcjgfcbnj-cpu.github.io/hemoni-preview/demo.html)，无需下载、登录或填写 API Key。

- 在报告页点击「修改内容」，或在核对页点击「完成核对并修改」。
- 对照核查时原文编辑修改稿，关联核查依据并记录修改说明。
- 保存待复核或确认保存，重开后查看修改稿及历史版本。
- 原核查记录保留，修改稿单独保存；支持 JSONL 导出和过期写入拦截。

案例与核查提示沿用原稿的预置演示数据，不调用 AI，也不进行通用材料核查。记录仅保存在当前浏览器，请勿输入私人材料。旧版自制工作台的广场、Token 监控和规则试跑不属于本次原稿 Demo 的操作入口。

## 为什么做这个项目

AI 输出可能出现数字正确但口径错误、引用无法定位、原稿与改稿之间缺少依据等问题。较真一下希望把「生成答案」之后的整理、核查、人工确认和案例积累连接起来。

例如，合同中的补偿门槛和奖励比例碰巧都是 75%，不能仅凭数字相同就判定答案正确，还要确认答案实际引用的是哪个字段。

## 桌面产品能力

以下是桌面项目中已实现或已集成的主要模块，不代表当前网站能实际执行这些功能。

| 模块 | 作用 |
| --- | --- |
| 桌面宠物 | 提供文字、文件、工作动态和常用功能入口 |
| 文件站 | 管理原始材料、AI 回答、编辑产物、版本及关联记录 |
| 较真工作台 | 导入材料，检查数字、单位、报告期间、引用和受支持的字段口径 |
| 证据定位 | 保存原句、文本位置、文档版本及可用的页码或工作表信息 |
| 回答编辑与核查修订 | 对照原文和改稿、关联证据、保存待复核、确认应用并查看历史 |
| 专家判断提炼 | 根据人工确认的字段角色、适用条件和同期证据生成候选评分规则 |
| 社区交流 | 帖子、回答、采纳、私信、收藏、通知及治理相关实现 |
| 模型调用 | 统一路由外部模型 API 与本地模型推理 |
| Token Guard | 展示 Token 用量速率、异常提示及工作流相关统计 |

## 核查如何进行

1. 导入原始材料与待查内容，解析为文档、正文块、段落和表格信息。
2. 为证据绑定文档版本、文本偏移、原句及可用的位置元数据。
3. 通过主题、文本相似度、数字特征和上下文寻找候选对应关系。
4. 使用确定性程序检查受支持的数字、单位、期间和算术关系，按配置结合模型辅助判断。
5. 展示差异和证据，由使用者复核；保存报告及历史记录。
6. 专家确认修改后，保留修订前后内容和依据，用于形成可追溯案例。

候选评分规则目前主要覆盖单数值字段口径，需要人工确认并在其他案例中验证。项目没有在桌面应用内训练通用金融大模型，也不提供通用 Excel 公式重算。

## 技术栈

| 范围 | 技术 |
| --- | --- |
| 本仓库展示页 | HTML、CSS、原生 JavaScript、Canvas、IntersectionObserver |
| 桌面应用 | Electron、Node.js、HTML、CSS、JavaScript、IPC |

| 社区 | Supabase、PostgreSQL、SQL/PL/pgSQL、Auth、RPC、Realtime |

## 当前边界

- 桌面端以 Windows 开发与验证为主；其他平台以实际发行版本和验收记录为准。
- OCR、复杂表格和跨材料匹配可能不完整，核查结果需要结合原件复核。
- 本仓库没有可连接的社区后端配置；数据库迁移和真实服务不随静态网页部署。
- 不以展示数据推断用户量、核查准确率、性能或成本收益。
